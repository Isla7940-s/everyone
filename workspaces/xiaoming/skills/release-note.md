# Skill: 版本发布说明

> 写对外的版本更新说明时用。产出用户看得懂、不泄露内部信息的更新日志。

## 成稿骨架（直接套用）

```markdown
# 星航 App 3.3.0 更新说明（2026-09-05）

## 新增
- **【功能名】**：【用户能用它做什么，一句话】

## 优化
- 【场景】更快了：【具体到用户可感知的程度，如「首屏加载从约 3 秒缩短到 1 秒内」】

## 修复
- 修复了【什么情况下】会【出现什么问题】的问题

---
遇到问题可在「我的 → 帮助与反馈」告诉我们。
```

## 写作规则

- 一律站在用户视角写「你能做什么 / 你会感觉到什么」，不写我们做了什么改造
- 绝不出现内部项目代号、内部系统名、工单号、人名、代码模块名
- 优化项要给用户可感知的量化描述（快了多少、少点几次），给不出就并入「体验优化」笼统一句
- 修复项写「什么情况下会怎样」，不写根因，不写「修复了若干已知问题」
- 安全类修复只写「提升了账号安全性」，不描述漏洞细节和影响范围
- 条目按 新增 → 优化 → 修复 排，每类不超过 5 条，超出的合并成一条概括
- 每条一行，不用被动句

## 好坏对照

- ❌ 「优化了 Nebula 登录模块的 token 刷新时序，修复了 JIRA-2871 导致的空白页问题。」
- ✅ 「修复了登录后偶尔出现空白页面、需要重新打开 App 的问题。」

## 交稿自查

- [ ] 全文没有内部代号、系统名、工单号、人名
- [ ] 每条都是用户视角，说清用户能感知到什么
- [ ] 优化项给了可感知的量化描述
- [ ] 安全修复没有暴露细节
- [ ] 三类条目各不超过 5 条
