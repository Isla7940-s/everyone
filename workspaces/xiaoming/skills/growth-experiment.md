# Skill: 增长实验方案

> 设计 A/B 实验或灰度实验时用。产出一份「上线前能过数据口径评审、下线时能判定输赢」的方案。

## 成稿骨架（直接套用）

```markdown
# 实验：【一句话说清改了什么】（EXP-2026-0x）

## TL;DR
假设【改动】能把【指标】从【现状】提到【目标】，靠【机制】。跑【天数】，样本【量级】。

## 假设
- 现状：【指标】= 【数值】（口径：【怎么算的】，来源：【哪张表 / 哪个看板】）
- 猜测原因：【为什么现在不行】，依据是【数据 / 调研 / 反馈】
- 改动：【具体做什么】
- 预期：【指标】提升【绝对值 / 相对值】，因为【机制链条：改动 → 用户行为变化 → 指标变化】

## 指标
| 类型 | 指标 | 口径 | 目标 |
| --- | --- | --- | --- |
| 核心指标 | 【只能有一个】 | | |
| 护栏指标 | 【不能变差的，如次留、崩溃率】 | | 跌幅 < 【x】% |
| 观察指标 | 【辅助解释的】 | | — |

## 实验设计
- 分流：【按设备 / 用户 id 哈希】，实验组 【x】% / 对照组 【x】%
- 样本量：【N】，按基线【p】、最小可检测提升【MDE】、显著性 0.05、功效 0.8 估算
- 周期：【x】天（≥ 1 个完整周，覆盖工作日与周末）
- 分层：新用户 / 老用户分开看（本项目 Q3 重点在新用户次留）

## 判定规则（上线前先定死）
- 赢：核心指标提升 ≥ 【x】且 p < 0.05，护栏指标未破线 → 全量
- 平：未达显著 → 保留对照，写清下一步试什么
- 输：核心指标下降或护栏破线 → 立即关停，24 小时内出复盘

## 停止条件
- 【触发即刻关停的红线，如崩溃率翻倍、支付成功率跌 2%】

## 排期
- 口径评审（老王把关）：【日期】｜ 上线：【日期】｜ 中期体检：【日期】｜ 结论：【日期】
```

## 写作规则

- 核心指标只准有一个，多了就是没想清楚要什么
- 护栏指标必填，至少包含次日留存和一个稳定性指标
- 判定规则必须在上线前写死，绝不允许看到数据再定标准
- 样本量要给估算过程（基线、MDE、显著性、功效），不能只写一个数
- 所有口径必须与老王的报表平台对齐，写明取数表名；口径未对齐的实验不许上线
- 假设要写出完整机制链条，「优化一下应该会更好」不算假设
- 每条不超过一行

## 好坏对照

- ❌ 「优化注册流程，预期提升转化率和留存。跑一周看数据。」
- ✅ 「假设：注册第 2 步的 6 位验证码输入框改为自动填充，能把注册完成率从 71% 提到 76%。机制：埋点显示 63% 的流失发生在验证码页，且平均停留 41 秒，说明是输入成本而非意愿问题。核心指标：注册完成率（口径：进入注册页 → 完成设密码，dwd_user_register）。护栏：新用户次留跌幅 < 1pp。样本 2×1.8 万（基线 71%，MDE 5pp，α=0.05，power=0.8）。」
