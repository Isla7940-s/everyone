# Skill: 界面文案

> 写或评审界面文案（按钮、提示、空态、错误信息）时用。产出可以直接进设计稿的文案表，不是文案建议。

## 成稿骨架（直接套用）

```markdown
# 【页面/模块】文案表（vX）

| 位置 | 状态 | 文案 | 说明 |
| --- | --- | --- | --- |
| 主按钮 | 默认 | 保存草稿 | 动词开头，说清结果 |
| 主按钮 | 禁用 | 保存草稿 | 置灰原因用辅助文案给出 |
| 辅助文案 | 禁用时 | 填写标题后可保存 | 告诉用户怎么解锁 |
| 错误提示 | 网络失败 | 网络不太稳，草稿已暂存本机。点击重试 | 三段式：事实+影响+出路 |
| 空态 | 无数据 | 还没有任务。去群里说一句「周五前我…」试试 | 给第一步动作 |
```

## 写作规则

- 按钮：动词开头，点了会发生什么就写什么（「保存草稿」不是「确定」）；破坏性操作把对象写进按钮（「删除这 3 条记录」），绝不用「确定/取消」二连
- 错误提示三段式：出了什么事 → 对用户的影响 → 现在怎么办；「怎么办」必须可点或可执行（重试 / 换方式 / 找谁）
- 空态不许只写「暂无数据」，必须给第一步动作
- 等待超过 3 秒的场景要说明在做什么、预计多久
- 同一动作全 App 同一个词（登录 ≠ 登陆；提交 ≠ 确认提交），交稿时附「用词对照」一行

## 禁忌（违反任何一条打回）

- 语气词「哦 / 呢 / 哟 / 啦 / 呀」
- 双重否定（「不是不能保存」）
- 甩锅式提示（「用户输入有误」→「手机号少了一位，请补全」）
- 中英文/数字之间不空格；半角标点混用

## 好坏对照

- ❌ 「操作失败，请稍后重试哦」
- ✅ 「验证码发送失败，可能是运营商拦截。30 秒后可重发，或改用语音验证码」
- ❌ 空态：「暂无内容」
- ✅ 空态：「还没有走查记录。从『新建走查』开始，或导入上期 checklist」

## 交稿自查

- [ ] 每条文案标注了位置 + 状态（默认/悬停/禁用/报错）
- [ ] 错误提示都有出路
- [ ] 全表无禁忌词、标点全角、中英数字间有空格
- [ ] 用词对照检查过（同动作同词）
