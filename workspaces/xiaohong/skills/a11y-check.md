# Skill: 无障碍走查

> 对界面做无障碍 / 对比度检查时用。产出一份带实测数值、可直接改的整改清单（不是「建议加强可读性」）。

## 成稿骨架（直接套用）

```markdown
# 【页面】无障碍走查（2026-08-28 · 标准 WCAG 2.1 AA）

## 结论
共 【N】 项不达标，其中阻断级 【N】 项。最严重的是【一句话】。

## 不达标清单
| # | 位置 | 问题 | 实测 | 标准 | 建议改法 | 级别 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 首页 / 次要文字 | 对比度不足 | 3.1:1 | ≥ 4.5:1 | #999 → #666（实测 5.7:1） | P1 |
| 2 | 暗色 / 主按钮 | 对比度不足 | 2.8:1 | ≥ 4.5:1 | 主色暗色态改 #4E83FF | P1 |

## 检查项与结果
- [x] 正文对比度 ≥ 4.5:1，大字号（≥18px 粗体 / ≥24px）≥ 3:1
- [x] 暗色模式同样满足以上对比度
- [ ] 不只靠颜色传达信息（错误态需同时有图标或文字）
- [ ] 点击热区 ≥ 44×44
- [ ] 图片 / 图标有替代文本，纯装饰图标标记为可忽略
- [ ] 焦点顺序符合阅读顺序，焦点态可见
- [ ] 字号放大到 200% 不截断、不重叠
- [ ] 表单错误提示与输入框有明确关联
- [ ] 动效可跟随系统「减弱动态效果」关闭

## 不改的项
- 【项】：不改的理由是【什么】，风险是【什么】，记入已知问题跟踪
```

## 写作规则

- 每条问题必须给实测数值和标准值，「颜色偏浅」不算问题描述
- 建议改法要给具体色值 / 尺寸，并附改完之后的实测值，让前端复制就能用
- 亮色和暗色两套主题分别测，本项目暗色模式对比度是已知薄弱项，必须逐项过
- 级别按用户影响判：完全不可用 P0 / 特定人群不可用 P1 / 有替代路径 P2
- 结论用「问题 → 影响 → 建议」三段式，不堆形容词
- 决定不改的项也要写进文档并说明理由，别悄悄跳过

## 好坏对照

- ❌ 「部分文字颜色偏浅，建议加强可读性，提升无障碍体验。」
- ✅ 「首页信息流的时间戳 #999999 在 #FFFFFF 上对比度 3.1:1，低于 AA 的 4.5:1，弱视用户在户外强光下基本读不到。建议改 #666666（实测 5.7:1），暗色模式下对应改 #A8A8A8（在 #1A1A1A 上实测 7.2:1）。级别 P1。」

## 交稿自查

- [ ] 每条问题有实测值、标准值、具体改法
- [ ] 建议改法附了改完后的实测值
- [ ] 亮色 / 暗色两套都测过
- [ ] 清单里的检查项逐项标了结果
- [ ] 每条都定了级别
- [ ] 不改的项写了理由和风险
