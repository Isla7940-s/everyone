# Skill: 数据口径说明

> 定义或澄清一个指标口径时用。产出一份「谁按它取数都得同一个值」的说明书，顺带写清常见误用。

## 成稿骨架（直接套用）

```markdown
# 指标口径：【指标名】（版本 v1.2 · 2026-08-28 生效）

## 一句话定义
【指标】= 【最精确的一句话，含时间范围与去重维度】

## 计算口径
- 统计粒度：【日 / 周】｜ 时区：Asia/Shanghai｜ 日切点：00:00
- 分子：【什么】
- 分母：【什么】
- 去重维度：【设备 id / 用户 id】
- 包含：【明确算进来的情况】
- 排除：【明确不算的：内部测试账号、爬虫、退款单…】

## 取数
- 主表：【库.表】（新数仓）｜ 旧表：【库.表】（老数仓，10 月底下线）
- 参考 SQL：
  ```sql
  SELECT ...
  ```
- 数据延迟：【T+1 / 小时级】，最晚就绪时间【几点】

## 常见误用
| 误用 | 后果 | 正确做法 |
| --- | --- | --- |
| 【用了另一张表】 | 偏高约 【x】% | 【用哪张】 |
| 【按用户去重】 | 与周报对不上 | 本指标按设备去重 |

## 与相邻指标的关系
- 与【指标 B】的差别：【一句话】，两者数值差约 【x】%，属正常

## 变更记录
| 版本 | 日期 | 改了什么 | 影响 |
| --- | --- | --- | --- |
| v1.2 | 2026-08-28 | 排除内部测试设备 | 历史值下修约 0.8% |
```

## 写作规则

- 定义必须精确到时区、日切点和去重维度，三者缺一就会出现两个人算出两个数
- 「包含」和「排除」都要显式写出来，尤其是退款、测试账号、跨天会话这类边界
- 参考 SQL 必须可直接执行，字段名与线上表一致
- 迁移期同时给出新旧数仓两张表，并写清两边的差异幅度
- 口径变更必须记版本和对历史值的影响，不允许原地悄悄改
- 与容易混淆的相邻指标要写清区别和正常差异幅度
- 对齐现有约定：DAU = 当日启动去重设备数；「有效访问」= 停留 > 3s

## 好坏对照

- ❌ 「DAU 指每天的活跃用户数，从用户行为表统计。」
- ✅ 「DAU = 自然日（Asia/Shanghai，00:00 日切）内有过至少一次 App 启动的去重设备数。去重维度是设备 id 而非用户 id（未登录用户也计入）。排除内部测试设备白名单（约 1200 台）与已识别爬虫 UA。主表 dws.app_active_device_di（新数仓，T+1，每日 07:30 就绪）；老数仓 ods.device_active_d 口径未排除测试设备，数值高约 0.8%，10 月底下线前请勿再用。」
