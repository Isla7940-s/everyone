# Skill: 周报

> 写个人 / 小组周报时用。产出让上级不追问的周报：做完了什么、卡在哪、下周做什么，全部可核对。

## 成稿骨架（直接套用）

```markdown
# 【你的名字】周报（08-24 ~ 08-30）

## 一句话
【这周最值得说的一件事，带结果数字】

## 已完成
- 【事项】：【结果，带数字或链接】（原计划 08-27 交，实际 08-27）
- 【事项】：【结果】

## 进行中
- 【事项】：进度 60%，卡在【具体卡点】，预计 09-02 完成

## 风险 / 需要支持
- 【风险】：影响【什么】，需要【谁】【做什么】，最晚【日期】前

## 下周计划
- 【动词开头的一件事】 → 交付物：【什么】，时间：【日期】
```

## 写作规则

- 「已完成」只写真正交付出去的，做了一半的一律进「进行中」并写百分比
- 每条都要能核对：带数字、带链接、带日期，三者至少有一个
- 「进行中」必须写卡点，写不出卡点说明其实是没开始
- 风险要写清楚「需要谁做什么」，只喊「有风险」等于没写
- 下周计划条数控制在 5 条以内，多了就是没排优先级
- 不写「继续推进」「持续跟进」这类没有信息量的动词

## 好坏对照

- ❌ 「本周继续推进注册链路优化，进展顺利，下周继续。」
- ✅ 「注册链路验证码到达率从 82% 提到 94%（8/26 上线，样本 1.2 万次）。剩余失败集中在联通号段，已找运营商排查，预计 09-02 有结论。」

## 交稿自查

- [ ] 「一句话」里有具体结果，不是形容词
- [ ] 已完成的每条都可核对（数字 / 链接 / 日期）
- [ ] 进行中的每条都写了卡点和预计完成时间
- [ ] 风险写明了「需要谁做什么」
- [ ] 下周计划 ≤ 5 条，每条有交付物和日期
