# Skill: 操作手册

> 把一件重复要做的事（发布、扩容、对账、导数据）写成手册时用。产出的手册要让没做过的人照着做也不会出事。

## 成稿骨架（直接套用）

```markdown
# 【操作名】操作手册

- 适用场景：【什么情况下执行】
- 不适用：【什么情况下不能用这份手册，改走哪个流程】
- 预计耗时：【X 分钟】｜ 需要权限：【具体权限名】｜ 影响面：【会不会影响线上】

## 开工前检查
- [ ] 【前置条件，例：已在群里同步过，值班同学在线】
- [ ] 【已备份 / 已确认回滚路径】

## 步骤
1. 【动作】
   ```bash
   【可直接复制执行的命令】
   ```
   预期输出：【看到什么算成功】
   如果看到【什么】：说明【什么】，处理办法是【什么】
2. 【动作】

## 验证
- [ ] 【怎么确认真的成功了，给可执行的检查方式】

## 回滚
> 什么情况下必须回滚：【判断标准，例：错误率 5 分钟内未回落】
1. 【回滚步骤，同样给命令和预期输出】

## 出事找谁
- 一线：【谁】｜ 升级：【谁】｜ 相关系统负责人：【谁】
```

## 写作规则

- 每一步都要给「预期输出」，没有预期输出的步骤等于让人蒙着做
- 命令必须可直接复制执行，占位参数用 `【】` 明确标出，不留隐含前提
- 危险步骤（删除、覆盖、重启）前面加一行醒目提示，写清楚做错的后果
- 回滚方案是必填项，写不出回滚就说明这个操作还不该被自动化
- 步骤按「一步一个动作」拆，一步里塞三件事就拆成三步
- 手册末尾留「最近一次验证时间」，超过三个月未验证的手册要标注可能过期

## 好坏对照

- ❌ 「3. 重启相关服务，确认服务正常后继续。」
- ✅ 「3. ⚠️ 重启网关（会断开存量长连接，约影响 3 秒）
  `kubectl rollout restart deploy/gateway -n prod`
  预期输出：`deployment.apps/gateway restarted`，30 秒内 `kubectl get pod -n prod | grep gateway` 全部 Running。
  如果有 Pod 卡在 CrashLoopBackOff：说明配置有问题，立刻执行「回滚」第 1 步，不要重试。」

## 交稿自查

- [ ] 写了适用与不适用场景
- [ ] 每步有可复制命令 + 预期输出 + 异常处理
- [ ] 危险步骤有醒目提示和后果说明
- [ ] 有独立的验证章节和回滚章节
- [ ] 写了升级路径（出事找谁）
- [ ] 标注了最近一次验证时间
