# Skill: 方案选型

> 在几个技术方案 / 产品方案 / 供应商之间做选择时用。产出一份「换个人看也能被说服」的决策备忘，而不是一张优缺点表。

## 成稿骨架（直接套用）

```markdown
# 【要决策的事】选型结论：选【方案 X】

## 结论与理由（3 行以内）
选【X】。核心理由是【决定性的那一条】，代价是【接受了什么】。

## 决策标准（按权重排序）
1. 【标准】（权重 高）：为什么它最重要
2. 【标准】（权重 中）
3. 【标准】（权重 低）

## 方案对比
| 维度 | 方案 A | 方案 B | 方案 C |
| --- | --- | --- | --- |
| 【标准 1】 | 【事实，带数字】 | | |
| 成本 | 【人日 / 金额】 | | |
| 风险 | 【最坏情况】 | | |

## 被否掉的方案
- 方案 B：否掉的**唯一决定性原因**是【什么】（不是「综合来看不如 A」）

## 前提与失效条件
- 本结论成立的前提：【假设】
- 如果【某条件变化】，应重新评估并改选【哪个】

## 落地下一步
- 【谁】在【日期】前【做什么】
```

## 写作规则

- 先定标准再比方案；不许先选好了再倒推理由
- 对比表里只填事实（数字、实测、文档条目），观点写在结论段
- 每个被否的方案要给出一条决定性原因，「综合较弱」不算原因
- 必须写代价：选了 X 放弃了什么、埋了什么坑
- 必须写失效条件，让后来人知道什么时候该推翻这个决定
- 不确定的数据标「估算」并写出估算方式，不要伪装成实测

## 好坏对照

- ❌ 「A 方案功能全、生态好、社区活跃，综合评估选 A。」
- ✅ 「选 A。决定性理由：我们要在 10 月底老数仓下线前完成迁移，A 有现成的双写工具（实测 200 万行 / 18 分钟），B 需自研双写，评估 12 人日，排不进 Q3。代价：A 的单表列数上限 1024，报表宽表要拆两张。」

## 交稿自查

- [ ] 结论在第一屏，且给了决定性理由
- [ ] 决策标准先于方案给出，并排了权重
- [ ] 对比表里全是事实，没有形容词
- [ ] 每个否掉的方案有一条决定性原因
- [ ] 写了代价和失效条件
- [ ] 落地下一步指定到人和日期
